# SCKB working agreements

- Mantén el contenido agnóstico: describe procesos y decisiones, no defaults de un proveedor.
- Separa las preguntas que inspiraron el atlas de la evidencia usada para responderlas. No publiques transcript, imágenes de la llamada, nombres, datos personales ni afirmaciones no verificadas.
- Cada flujo técnico nuevo o corregido debe tener una fuente primaria pertinente en `content.js`. Etiqueta ejemplos y variaciones como tales.
- Conserva el sitio estático, accesible con teclado, usable en móvil y sin dependencias innecesarias.
- Verifica sintaxis, referencias de contenido, interacción principal y URL publicada antes de declarar entrega.
- Usa el proyecto como una guía ligera; no importes la gobernanza privada de AEKR ni sus archivos protegidos.
